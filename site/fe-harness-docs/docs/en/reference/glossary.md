# Glossary

## Harness

An engineering protocol centered around project facts, constraints, verification, and traceability.

## Core

Business-agnostic runtime responsible for configuration, diagnostics, verification, reporting, and safe writes.

## Product Profile

Product form rules, such as Consumer H5.

## Platform Adapter

Runtime platform rules, such as Web Mobile.

## Stack Adapter

Framework and toolchain rules, such as uni-app.

## Input

Raw evidence, including PRD, RP, UI, API, and assets.

## Design Token

Project-unique machine-readable visual truth. It stores semantic values such as colors, font sizes, spacing, border radius, shadows, layers, and animations, and records source status.

## Token Authority

The authoritative source for token values. Priority order: high-fidelity UI, RP, user ad-hoc visual requirements, existing project tokens, DESIGN principles, Harness defaults, Agent inference.

## Requirement Closure

Requirement closure requires that reachable pages, states, actions, and return paths in PRD/RP are verified, deferred, or recorded as external blocking.

## Managed File

Files generated by Harness with metadata protection. After manual modification, subsequent generation should refuse to overwrite.

## Aggregate Skill

Aggregate workflow Skills installed by default, such as `consumer-h5-harness`.

## Command-specific Skill

Skills for specific commands or specialized capabilities, such as `fe-harness-api` and `fe-harness-design-tokens`.
